# Features

The full feature list; [README.md](../README.md#features) has the summary.

- Web reader: keep the sender and Reply visible, expand full message details and keywords, and use More actions for archive, snooze, flag, read/unread, spam, print, remote content and delete. Remote content remains blocked until explicitly enabled for that message.

- Repeatable installer setup: runtime-owned `apply-setup --file [--check]` and capability discovery preserves existing SSO/webhook/domain/recovery configuration and returns a secret-free JSON report. Target-held credential file references avoid installer secret copies. `setup-status` lists configuration blockers and external acceptance checks. See [clean installation](INSTALLER_SETUP.md).

- Guided dedicated-domain qualification: `bash scripts/setup-mail.sh <public-KyPost-origin>` walks through native deployment, KyIdentity/DNS proof, operator relay, protected engine/TLS inputs, backups and receiving launch. It requires Docker-operator authority and explicit configuration/start confirmations; live delivery remains an operator check. See [guided setup](RECEIVING_SETUP.md#guided-operator-setup).

- Optional local Rspamd sidecar rejects messages meeting the configured spam threshold before native SMTP acceptance. False positives can reject legitimate mail; scanner outages defer new mail, and enabling it gives the scanner message access. Accepted mail remains unchanged. See [spam setup](RECEIVING_SETUP.md#optional-rspamd-sidecar).
- Continuous Cloudflare receiving (offline-qualified, not yet qualified live): with `KYPOST_CLOUDFLARE_RECEIVING_ORIGIN` set, the daemon publishes a signed routing table of every admitted address to the operator's Email Worker and picks mail up from its private R2 queue over outbound HTTPS every 30 seconds. Each message is checked against the owner and address generation frozen when Cloudflare accepted it, scanned by the local Rspamd sidecar (a reject verdict files it to Junk, since accepted mail cannot bounce) and committed to the mailbox before the provider copy is deleted. A restored copy starts fenced; `kypost-server receiving cloudflare takeover` moves receiving to it and locks the previous host out. See [continuous receiving](CLOUDFLARE_CONTINUOUS_RECEIVING.md) and [operator commands](RECEIVING_SETUP.md#continuous-cloudflare-profile).
- One-message Cloudflare receiving pilot: an operator-owned Email Worker retains exact mail in a private R2 slot for manual authenticated HTTPS pickup into a native mailbox. Local scanning follows provider capture; refusal retains the provider copy. This finite-window test is not continuous reception. See [setup, trust and rollback](CLOUDFLARE_RECEIVING.md).
- Controlled direct receiving profile generation from verified domain and existing native storage; mandatory STARTTLS refuses plaintext senders. An optional Compose profile supervises the operator-supplied pinned receiver, which shares the instance’s mail-storage authority; public deployment remains gated. See [receiver setup](RECEIVING_SETUP.md).

- Sending quota for every account, 60 messages an hour and 1000 recipients a day by default. Admins change it under Application or per account under Users. It is kept in the install-wide state database, so the web, the apps and scheduled mail share one count.
- Send delay (Settings → Mail → Send delay: Off, the default, or 10, 20, 30, 60 or 90 seconds). Send holds the message on the server for that long, through scheduled send, so closing the tab or a restart neither sends it early nor loses it. While it waits, the web app shows "Sending in Ns" with **Cancel sending**, and the Scheduled page lists it from any client; canceling returns it to Drafts with recipients, body and attachments, and it does not count against the sending quota. Once it has gone it cannot be recalled. Encrypted mail is held already encrypted. Calendar replies and secure-link sends go at once.
- Scheduled send from compose (Schedule…: in an hour, tomorrow morning, Monday morning or a chosen time) for IMAP and native mailboxes, plain and PGP. The message is frozen and dated at the send time; if account security, keys, the sending device or the From address change first, it returns to Drafts unsent with the reason. The Scheduled page lists status and reason and cancels waiting mail back to Drafts. Pending mail is sealed under `$SECRET_DIR/scheduled-send.key`; losing that key makes it unrecoverable. A restore returns waiting mail to Drafts rather than sending it twice.

- Opt-in native sending (primary address or an administrator-assigned active alias) through the operator-owned relay: ordinary compose and client PGP record encrypted outbox intent before SMTP; recovery retains interrupted claims, retries definite temporary refusals and files Sent independently. Failed relay attempts log a bounded SMTP code and outbox correlation ID without provider text or correspondence. Included in sealed backups; see [outbox contract](NATIVE_OUTBOX.md).

- Admin → Server → Mail domain lists every configured mail domain (add, verify, retire, re-add; per-domain TXT proof and status), chooses the relay's sending domains and guides DNS proof, encrypted operator-owned relay configuration and a no-mail TLS/authentication check, protected by account confirmation and fresh DNS proof. KyPost holds the domain-wide relay credential on the server. Native sending requires explicit native mode and fresh sender admission; saving credentials does not prove delivery or public receiving readiness; see [setup and controlled tests](DOMAIN_RELAY.md).

- Plus addressing for hosted mailboxes and their aliases: mail to `you+anything@domain` arrives at `you@domain` (an existing address that itself holds a `+`, such as a KyIdentity primary `john+work@`, still matches exactly; otherwise the part before `+` decides), a reply sends from the same plus address, and mailbox rules can test the tag (`address :detail`, or "tag after +" in the rule builder). On by default; Settings → Mail → Masked & plus addresses turns it off, refusing such mail like an unknown address. New aliases, masked addresses and administrator-created mailboxes never hold a `+`; KyIdentity primaries are kept as sent.
- Masked and disposable addresses for hosted mailboxes (Settings → Mail → Masked & plus addresses): users make random addresses such as `quiet.otter.4821@<domain>` with an optional note, pause, resume and delete them, and disposable ones expire after 24 hours, 7 days or 30 days. Mail sent from one goes out as that address alone (From, envelope sender, Message-ID; no Reply-To, Autocrypt, DKIM `i=` or out-of-office reply that would name the primary). A paused, expired or deleted address is refused exactly like an unknown one; a deleted one stays reserved and is never reissued. Up to 100 per user and 20 new a day; their mail counts toward the owner's sending quota. Off until an administrator ticks a domain under Admin → Server → Mail addresses → Masked addresses.
- Admin → Server → Mail addresses lists native mailboxes and their addresses (kind, state, generation; filter by user), adds aliases to an everyday identity's mailbox, releases them (kept reserved; delivery and sending stop at once, existing mail stays) and reassigns reserved ones to a chosen mailbox, and creates, disables and re-enables additional mailboxes for an everyday identity, each with account or KySignOn confirmation. Primary mailboxes and addresses come from KyIdentity and offer no actions; see [addresses](NATIVE_PROVISIONING.md#addresses-aliases-and-generations).
- Administrators block abusive senders by address or domain (Admin → Server → Sender blocks, `receiving blocks` CLI or admin API); both receiving profiles refuse them before storing anything. With the Rspamd sidecar, Maddy also blocks a sender automatically after 5 spam rejections in an hour, but only when SPF and aligned DKIM prove the sender address (1 hour, then 24 hours, then 7 days), and a whole domain only after 5 such addresses on a domain you never received authenticated mail from (after 30 days of collecting that history). Automatic blocks use at most half the list and always give way to administrator blocks. The Sender blocks tab shows every block in force (automatic domain blocks called out in words, since one can cover a whole provider) and the automatic-evidence status: damaged or reset evidence, when automatic domain blocks start, and when automatic blocking or the protected-domain record is full. Removing any block suppresses automatic re-blocking of that exact address or domain for 30 days. See [sender blocks](NATIVE_PROVISIONING.md#sender-blocks).
- Admin → Server → Quarantine lists quarantined native deliveries by envelope only (received time, sender, recipients with their frozen mailbox and user, size, gateway/ID; never body or subject), shown as plain text with hidden characters made visible, and releases each to its original mailboxes or discards it permanently, with account or KySignOn confirmation; see [quarantine release](NATIVE_PROVISIONING.md#quarantine-release).

- First sign-in encryption setup: create or import a key in the browser, store a recovery copy after confirming its recovery code is saved, and choose "Encrypt all incoming mail" (on by default); the key is published through WKD as before. Admin → Server → Security sets Encryption key (Required by default, or Optional with "Not now") and Encrypt incoming mail (Required, On by default, Off by default); Manage Users has "Require key setup" per user. While setup is owed, mail is withheld on the web from the next sign-in and on devices and agents at once (`encryption_setup_required`). Administrators never generate, see or hold a key. Required is refused while the SSO provider is not KySignOn; SSO-only users of such a provider skip the step. [Contract](E2E_PGP.md#first-sign-in-setup).
- Per-user opt-in incoming encryption under Security → Encryption: classify unread, unprocessed inbox mail, then replace it with a verified public-key-encrypted copy. Requires a client-protected key, saved-key-backup acknowledgment and fresh account confirmation. The provider sees plaintext before processing; losing the private key makes replaced mail unreadable. Unreplaceable messages remain plaintext with explicit failure decisions; [read the replacement and recovery contract](E2E_PGP.md#incoming-mail-encryption-opt-in).

- Sealed configuration/state backups to KyRecovery or a local directory, with admin scheduling and restore drills. Internal native mailbox/receiving databases use SQLite snapshots including committed WAL rows; historical ownership is checked, restored queued/retryable outgoing mail is quarantined against replay, native device/browser push registrations and pairing tokens are revoked (fresh pairing/enrollment required), offline restore raises native ID-token revocation cutoffs beyond the accepted 30-second future skew, and native restores remain held until released. Held native accounts cannot sign in or exercise existing session/admin authority; retain a separate legacy recovery administrator. Offline restore also rotates a separate reference generation without changing encryption namespaces; native reads/actions reject stale-generation or bare numeric references before access. Protected admin APIs can record fresh signed KyIdentity evidence and revision barriers for unpublished reservations; published accounts retain ordinary offboarding and demotion. A separate protected repair API reconciles published native activity/roles and revokes stale transport credentials while preserving mail, labels, passwords, PGP material and the restore hold. Hold release is implemented behind `KYPOST_NATIVE_RESTORE_RELEASE` (off by default, pending qualification); see [releasing the hold](RESTORE.md#releasing-the-hold). Custodian shares are used only by the offline restore command; see [sealed backup and restore](RESTORE.md). With `KYPOST_BULK_BACKUP_REPOSITORY` set, mailbox and receiving databases go to an encrypted restic repository instead of the capsule, which seals the snapshot ID and every file digest, so mailboxes are no longer limited to 64 MiB; native mail with real quotas (5 GiB per mailbox by default) needs it, since a capsule-only backup fails once a mailbox passes 64 MiB, with an error naming the variable. Prefer an append-only rest-server: a local repository is writable by KyPost, unlike deposit-only KyRecovery; see [mail bulk backup](RESTORE.md#mail-bulk-backup).
- Self-service mail import under Security → Import Mail: an mbox file, one EML or a zip of EML files into a native mailbox folder, after account or KySignOn confirmation, as a background job with progress and cancel. Messages are stored as parsed from the file and marked read; duplicates are skipped; imported mail is not scanned for spam or run through rules, even if later marked unread. A job handles at most 20,000 messages and an upload at most 20 minutes. Refused while incoming encryption is on, since imported mail would be stored unencrypted. Or import from another mail account over IMAP: the server signs in with a password or app password used only for that import, kept encrypted until the import starts (10 minutes at most) and never saved after that, lists the folders to choose from, and copies them read-only, keeping each message's read and flagged state and received date; it connects only to public servers over verified TLS.
- Users with additional native mailboxes switch between them in the webmail sidebar and read, search, file and send from each; compose offers the open mailbox's addresses as From. The choice lasts for the browser tab.
- Self-service mail export under Security → Export Mail: a native mailbox, or one folder, as an mbox file or a zip of EML files holding the exact stored bytes, after account or KySignOn confirmation. Encrypted messages stay encrypted; flags and labels are not included.
- Shared JSON application logs on stderr, controlled by `KY_LOG_LEVEL`; see [logging](../LOGGING.md).

- Single-container Docker runtime. supervisord manages the processes.
- Multi-user with two roles. Admins manage users and system settings. Each user connects their own IMAP mailbox, or with native mail on gets a KyPost-hosted mailbox; see [external IMAP](guides/IMAP.md) and [native mail](guides/NATIVE_MAIL.md). Signed KySignOn directory events retain desired account data; admins can configure and verify mail-specific DNS domain claims for several domains under one issuer (each with its own proof, retirable once unused), and a primary address may sit on any of them. Internal allocation prepares reserved native mailboxes before exposing new accounts; administrator identities get mailbox-less accounts. Native state access refuses held or unqualified storage before cache returns and uses an existing-only state opener. `KYPOST_NATIVE_MAIL=true` opts into new domain-account provisioning, native mailbox access and relay sending in API/daemon; separate `KYPOST_NATIVE_RECEIVING=true` enables local receiving commands and daemon import for controlled qualification. Every native mailbox has a storage quota (`KYPOST_MAILBOX_QUOTA_BYTES`, default 5 GiB), a 25 MiB message limit and 1,000,000 records; `migrate-native` applies a changed quota to existing mailboxes at the next start, and a lowered one never locks a mailbox, it only refuses new mail. Users see their usage under Settings → Mail → Storage, with warnings at 80% and 95%; Server → Mail addresses shows each mailbox's usage and warns when the quotas could outgrow the drive. Receiving answers a full mailbox and a nearly full drive (the reserve: 10% of the state filesystem or 5 GiB, whichever is larger) with temporary 452 replies so senders retry, and imports stop at the same reserve; see [mailbox quotas](NATIVE_PROVISIONING.md#mailbox-quotas). Bundled public receiving remains unavailable; see [the provisioning contract](NATIVE_PROVISIONING.md).
- IMAP inbox reader with background body preloading, folder management, and drag-and-drop move actions
- Conversation view in the web inbox, on by default and switched per user under Settings → Mail → Conversations ("Group messages into conversations"). Replies are grouped by `Message-ID`/`In-Reply-To`/`References`, with a time-limited subject fallback only where one side of a chain has no headers; your replies from Sent appear in the conversation without being moved. A row shows its senders, message count, newest date and rolled-up unread, flag and attachment state; list actions apply to the whole conversation, reader actions to the open message. The reader stacks messages oldest to newest with the newest unread one open; a search result opens inside its conversation. Grouping covers the 500-message window; native clients do not group yet. API: `GET /api/inbox/conversations` ([API](API.md)).
- Calendar invitations in the web reader: a card shows the title, time, place and organizer of the message's own invite (warning about a cancellation, an update, an organizer who is not the sender, an unknown time zone or a phishing flag) with Accept, Maybe and Decline for a request. An update to an invitation already answered in this browser says what changed (time, place, title) and asks again; a cancellation reads "Cancelled" with no answer buttons; an `https:` meeting link (`CONFERENCE`) shows a Join meeting button naming its host. The answer goes through KyCalendar when it is in use; otherwise, after the user confirms, an unencrypted, unsigned iTIP reply is mailed to the organizer.
- Verification-code card: a code in INBOX mail under 15 minutes old is shown with a Copy button and a never-share warning. It makes no claim about the sender and makes no network request; phishing-flagged mail gets no card
- Automatic keyword labels for unread mail. KyPost polls each active user's mailbox separately, and each account has its OWN label list — copied from the instance defaults when the account is created, then theirs to change. Labels are a sorting hint a determined sender can influence — see [Classification flow](ARCHITECTURE.md#architecture).
- On-device embedding sorter in front of the LLM: a ~30 MB embedding model baked into the image labels mail in well under a millisecond and sends only what it is unsure of to Ollama. It learns per account from you — change a message's label in the reader (or in another IMAP client; noticed when the KyPost inbox syncs) and similar mail follows; give a new label an optional description and it is recognised straight away. It stores vectors, never message text, and never trains on the LLM's own answers. `CLASSIFIER_ENGINE=llm` turns it off.
- Pre-sort before the model: mail from a contact you added is labelled `Primary` without an LLM call, and mail with mailing-list or automated headers (`List-Id`, `List-Unsubscribe`, `Precedence: bulk/list/junk`, `Auto-Submitted`) can never be labelled `Primary`. Same input, same answer; edit your contacts or add a rule to change it.
- Filter Rules: a GUI condition and action builder plus a raw Sieve script editor. A run-now panel applies the rules on demand. Rules can test any header, so a provider's spam verdict (for example `X-Spam-Flag: YES`) can move mail to Junk.
- Compose flow with SMTP send and IMAP draft save; invalid-recipient relay refusals name the address to correct and keep the message open.
- Flag: flag mail from the reader or the list, with a due choice (Today, Tomorrow, This week, Next week, No date). The flag is IMAP `\Flagged`, so other mail apps see it. With KyCalendar paired, a flag becomes a task in the user's KyCalendar Inbox list, and finishing, reopening or deleting the task clears or sets the flag again. The task links back to the message, or says the message is no longer available.
- Snooze: hide an email in a `Snoozed` folder until a chosen time, then return it to the inbox unread, with a notification, at the top of the list for 30 days (in KyPost; other mail apps show its original date). Wake is accurate to one poll interval.
- PGP mail encryption and signing. Signing defaults on with an unlocked browser key; compose labels unsigned mail, and the reader distinguishes encrypted but unsigned mail from a verified signature. Generate or import a key, search for recipient keys on keys.openpgp.org, and check recipient key status before you send. KyPost has two key-protection modes. Read [Where your PGP private key lives](PGP-KEYS.md#where-your-pgp-private-key-lives) before you rely on this.
- Email encryption for SSO-only accounts: an account with no password seals its PGP key under a separate encryption passphrase and confirms key changes with KySignOn
- Contacts address book with groups, dedupe, bulk delete, CSV and vCard import and export, and photo support. Mobile clients bringing kept contacts may explicitly ask the relay to import a contact without a key its validator refuses; ordinary key writes stay strict. A key learned from a correspondent's mail (Autocrypt) signs as "not confirmed" until you compare its fingerprint with them and choose Confirm key in their contact details (password or KyIdentity confirmation).
- CardDAV server (`/dav`, `/.well-known/carddav`) to sync contacts to phones and desktop apps; generating its app password takes your password or a KyIdentity confirmation. An optional CardDAV client syncs against an external address book. Native restore revokes historical CardDAV app passwords and blocks CardDAV while recovery is held.
- Browser PGP writes reject stale snapshots, including same-key edits concurrent with password changes or recovery uploads. Existing complete keyrings support atomic password changes that preserve all history and recovery material.
- PGP recovery copies stored as ciphertext, downloadable backups checked before creation completes, and browser-local recovery drills. Complete-ring export, drills and matching-backup restore preserve historical keys; restoration confirms the stored result before unlocking. Verified complete-ring server copies require saved-secret acknowledgement and confirm the stored result. Conversion and older-backup merging remain gated.
- Multi-factor authentication: TOTP authenticator apps, one-time recovery codes, and push-approval sign-in
- Single Sign-On against any standard OpenID Connect provider — KySignOn (one-click preset; the `kypost.admin` app role is the only thing that makes an administrator, and an SSO session never holds admin without it), for Authentik and Keycloak only an administrator group the operator names (exact group or realm role; none by default) provisions administrators. Authorization code + PKCE, ID tokens verified against the issuer's JWKS. Issuance timestamps must be positive and within 30 seconds of future server-clock skew; keep issuer/server clocks synchronized. Accounts are claimed by the provider's issuer and `sub` and never by username or email; changing the issuer revokes links made at the previous provider. Admin-configured under Admin > Server > SSO; **requires `SERVER_BASE_URL`**.
- Suite app rail: an account linked to KyIdentity sees the suite apps KyIdentity lets it open as icons at the foot of the sidebar (under the content on phones), KyPost marked as current. Each is a plain link to the app's KyIdentity sign-in, so the existing KyIdentity session opens it without a second login. Local accounts, other OIDC providers and a KyIdentity outage show no rail.
- KyCalendar pairing, automatic through KyIdentity when KyPost signs in through it (the suite directory gives KyPost KyCalendar's URL and shared secret, re-checked every 15 minutes and after a bad signature), or set by `KYPOST_KYCALENDAR_URL` and `KYPOST_KYCALENDAR_SECRET_FILE`, which win. Server → KyCalendar shows how it is paired, or why not. Each user's switch is under Settings → Mail → KyCalendar: on by default when KyIdentity paired it, off by default when the environment did; a stored choice always wins, including the off earlier versions saved for anyone who changed a setting. KyCalendar sends invitations, cancellations and replies through the user's own SMTP account (or, for a KyPost-hosted mailbox, the native outbox) and sending quota, from their address or a verified send-as alias, as a fixed message KyPost builds; KyPost refuses recipients the invitation does not name, and a reply to an organizer whose DKIM-signed invitation the mailbox never received. Incoming invitations, replies and cancellations are forwarded to KyCalendar only when DKIM-signed by the From address's own domain; everything else stays ordinary mail. RSVP answers go through `POST /api/calendar/rsvp`, which reads the invitation from the message itself. Trade-off: with it on, the paired KyCalendar can send calendar mail as you to anyone the invitation names. KyPost-hosted mailboxes send through the native outbox and domain relay instead, from any active address of the user's own mailboxes, with the same checks, quota and Sent copy. Contract: [KYCALENDAR.md](KYCALENDAR.md). When KyCalendar is in the user's suite app list, compose (New meeting: subject, To and Cc), a contact's menu (New meeting) and the reader (Reply with meeting: subject, sender and recipients without the user) open KyCalendar's event editor in a new tab, prefilled; nothing is saved until the user saves it there ([SUITE-INTEGRATIONS.md](SUITE-INTEGRATIONS.md), section E).
- KyPulse alert mail, paired only through KyIdentity (both apps signing in through it). Under Settings → Mail → KyPulse, "Let KyPulse send alerts from my mailbox" is off by default. While on, KyPulse may send a plain-text alert (`[KyPulse] ` subject, `Auto-Submitted: auto-generated`, no HTML, attachment or Reply-To) from the member's own address through their normal outbox (SMTP account or native outbox), filed in Sent and charged to their sending quota, to their own addresses (account address, verified send-as aliases, active addresses of their KyPost-hosted mailboxes) and up to 10 extra addresses, each of which must first confirm through a link mailed from that mailbox (opening it shows a button; only pressing it confirms; 7 days; a resend or removal kills the old link). At most 30 alerts per mailbox per hour. Contract: [KYPULSE.md](KYPULSE.md).
- Compose deep link `/compose?to=&subject=&body=` (KyDrive's "Email a link" uses it): opens a new draft prefilled with checked addresses, subject and plain-text body (links become links); nothing is sent or saved until the user acts, and it survives signing in ([SUITE-INTEGRATIONS.md](SUITE-INTEGRATIONS.md), section J).
- Recipient autocomplete suggests people in the organisation (from KyIdentity, for accounts signed in through it) under an "Organisation" heading after your own contacts, without duplicates. See [SUITE-PEOPLE.md](SUITE-PEOPLE.md).
- KyDrive pairing, automatic through KyIdentity or by `KYPOST_KYDRIVE_URL` and `KYPOST_KYDRIVE_SECRET_FILE`; Server → KyDrive shows it. For users who can open KyDrive and allow it in KyDrive settings, compose offers "Upload to KyDrive and send a link" for files over the attachment limit (and for any attachment), with upload progress and cancel, inserting the file name linked to an organisation-only link with its size and expiry. Before sending such a message KyPost checks the recipients against the organisation and names anyone who cannot open the link, offering to send anyway or attach the files instead, or, when KyDrive's administrator and the user allow it, to send guest links that expire (after confirming it is them within the last 10 minutes). Compose's **Attach from KyDrive** opens KyDrive's picker to share links to existing files or attach copies of them. Reading, each attachment can be saved to KyDrive's `Mail attachments` folder, and an Office or PDF attachment (docx, xlsx, pptx, odt, ods, odp, csv, pdf) of unencrypted mail can be opened read-only in Euro-Office (**Open**, a 24-hour viewing copy only the user can see) or saved and opened for editing (**Edit in KyDrive**); never for encrypted mail. Contract: [KYDRIVE.md](KYDRIVE.md).
- KyMessages pairing, automatic through KyIdentity or by `KYPOST_KYMESSAGE_URL` and `KYPOST_KYMESSAGE_SECRET_FILE`; Server → KyMessages shows it. For users who can open KyMessages, **Chat** beside the reader's Sender and in a contact's menu, shown only for people in the organisation, opens the direct chat with that person in KyMessages in a new tab; someone without a KyMessages account yet gets "This person isn't on KyMessages yet." See [KYMESSAGES.md](KYMESSAGES.md).
- AI agent access over MCP (`/mcp`, Streamable HTTP; tokens under Security → AI agents). Two access levels per token: Read only (default; folders, labels, search, read a message or thread) and Read and organize (also apply/remove the user's own labels, move, archive, save plain-text drafts). No tool sends or deletes, nothing moves into or out of Trash or Junk, moves only reach existing folders, and agent labels never train the sorter (the prediction is dropped first). Agent requests are metered per user across all their tokens (120, refilling two a second; listings and threads cost more; a refusal says how many seconds to wait) and run one at a time per user; search never returns encrypted messages and always fetches a full page, so its count says nothing about them. A search costs one unit plus five for each page of 25 matches it walks (the first page is what one search always cost); a broad search in a folder full of encrypted matches can need more than the 120, and then no wait is enough: narrow it by field or folder. End-to-end encrypted mail (PGP/MIME, any `multipart/encrypted`, S/MIME, inline PGP, or any encrypted part) is metadata only: addresses and date, no subject, body or attachment names; anything that cannot be parsed counts as encrypted. Results put sender-written text under `sender_controlled`, bodies come as plain text without links, capped at 32 KiB. Tokens are bearer-only, refused from browsers (any `Origin`), stored as a SHA-256 hash, at most 20 per user, revoked after 90 days unused, by a sealed-backup restore and by every credential revocation. Administrator identities get none. Trade-off: an agent with Read and organize can be talked into labelling, moving or drafting by text in a message; a draft is never sent without the user.
- Out-of-office reply under Settings → Mail → Out of office: one text for people in the organisation (suite members and the mail domains) and, when the administrator allows it, one for everyone else or only your contacts; an optional period; each sender answered once per four days; never mailing lists, automated mail, junk or senders whose DKIM does not match; replies are saved in Sent; an "Out of office is on" bar in the inbox turns it off. With KyCalendar, the period can show as an out-of-office event (busy) and new invitations can be answered Tentative while away. Contract: [OUT_OF_OFFICE.md](OUT_OF_OFFICE.md).
- Email signatures under Settings → Mail → Signatures: plain-text signatures kept on the server, so every KyPost client inserts the same ones; a default, a choice per sending address, and switches for replies and forwards. Compose adds it below the line you type on and above any quote, and follows a From change until you edit it. Contract: [SIGNATURES.md](SIGNATURES.md).
- Send-as aliases, each verified before use: a code is mailed as the alias to the alias through your own outgoing server. Typing it back unlocks the From address; the same message looping back DKIM-signed by the alias's domain is the proof that also publishes your key for it over WKD
- Web Key Directory publishing: serve your users' public keys at `/.well-known/openpgpkey/` for verified domains, so correspondents discover them without a keyserver
- CAPTCHA on login, **self-hosted proof-of-work by default** (also Turnstile or Friendly Captcha; `CAPTCHA_PROVIDER=none` turns it off). It works alongside a 3-strikes/15-minute account lockout, a looser per-IP lockout, and an instance-wide login rate limit. Office networks an administrator lists skip the per-IP limits only. Note that proof-of-work needs a secure context in the browser — read the CAPTCHA notes in `.env.example` if you serve over plain HTTP on a LAN.
- Browser push notifications for each user, for all mail or for keyword matches only. KyPost also supports native push pairing for mobile apps; a device paired from the QR code waits for your approval on the web page (model, OS, request address and a matching code) before it gets any access. Encrypted-mail setup checks the device’s supported envelope formats before sealing.
- Settings grouped into panels: Appearance, Mail (IMAP/SMTP, storage, send-as, signatures, contact sync, filters), Security (including mail import and export), Notifications and Status — plus Email Labels for each user's own prompt tuning and classification decisions — and an Admin group for server runtime and diagnostics
- Busnes light/dark defaults follow the OS; Settings → Appearance offers Match system and twenty-two suite theme presets as preview cards, saved in this browser only
Native direct outbound delivery is available as an explicit protected-API profile. It signs every message with a per-domain DKIM key, and Mail domain shows and checks the DKIM, SPF, DMARC and reverse DNS records and rotates keys on the administrator's request (recommended at 180 days), with a DNS-confirmed switch, a 7-day retire window and an emergency rotation; see [direct delivery](DIRECT_DELIVERY.md) for configuration, recipient outcomes and qualification limits. Existing relay sending remains the default.

## HR address allocation

KyIdentity can request a unique native work address before creating an SSO identity. Stable issuer/subject reservations survive retries and same-name collisions receive numeric suffixes. Address-only reservations create no usable account, mailbox storage or live receiving route. Normal signed directory provisioning consumes them after activation and app assignment. See [HR address reservations](NATIVE_PROVISIONING.md#hr-address-reservations).

## Post-quantum device enrollment

The server and browser support X-Wing HPKE device envelopes (v6, KEM 0x647A) with
SAS v2 binding the entire device public key. Existing P-256 v4/v5 enrollment stays
supported while native clients upgrade. This upgrades private-key delivery, independently
of an account’s OpenPGP certificate version. See [device enrollment](DEVICE_ENROLLMENT.md#normative-the-x-wing-hpke-envelope-v6).


## OpenPGP v6 readers (Spec A P3)

The browser's gopenpgp WASM engine reads RFC 9580 v6 and RFC 9980 composite keys,
decrypts ML-KEM-768+X25519 / ML-KEM-1024+X448 messages and verifies ML-DSA-65+Ed25519 /
ML-DSA-87+Ed448 signatures. Complete keyring v2 backups retain separate v4/v6 active
members plus all historical keys; v1 remains readable. Sealed envelopes allow 512 KiB;
recovery files allow 2 MiB. Devices report their OpenPGP codecs on both enrollment
endpoints and the device inventory exposes them. This does not switch existing
accounts by reading alone; the additive P4 upgrade below enables v6 after device qualification. See [wire contract](E2E_PGP.md#keyring-v2-reader-contract-spec-a-p3).

## Browser PQ keys (Spec A P4)

Security → Encryption adds a v6 30/35 certificate through gopenpgp WASM after a
checked complete recovery backup. V4 stays active and publicly interoperable.
Every paired device must report v6/RFC 9980 and confirm the current X-Wing ring
before incoming encryption, Sent and drafts use v6. Browser delivery groups split
PQ and classical copies, with matching signatures and each Bcc alone. Compose and
opened classical messages are marked **Not quantum-safe**; Sent retains classical
delivery addresses inside its ciphertext. [Wire and rollout contract](E2E_PGP.md#browser-pq-upgrade-spec-a-p4).
