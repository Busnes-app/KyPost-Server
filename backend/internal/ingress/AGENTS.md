# Ingress

## Purpose

Durable receiving buffer and immutable envelope ownership, separate from permanent mailboxes.

## Ownership

All files in this package. Opt-in app receiving commands and daemon import select it; no bundled public listener starts it. See [runtime contract](../../../docs/NATIVE_PROVISIONING.md#direct-receiving-runtime-qualification-profile).

## Local Contracts

- Callers are trusted local receiver/importer processes with exclusive access to an owner-only directory. Gateway IDs are supplied by authenticated transport configuration, never SMTP headers. This package is not a network authentication boundary.
- Route writers must verify KyIdentity provenance before calling `SetRoute`. Versions are the ledger address generation, monotonic per address; same-version refresh cannot change ownership or activation. `DeactivateRoutes` is the ledger writer's release/disable/reassign path under the directory fence: it writes existing routes inactive at a never-lower generation, refuses a lower one, and is a no-op without a store or route.
- `RefreshRoute` is accepted-mail recovery only: existing identical issuer/subject/mailbox/generation/active tuple, no insertion or reactivation. App import selects it only without fresh admission proof.
- Bind at RCPT; for the hosted Cloudflare profile, bind at pickup from the gateway's frozen (address, generation, table revision), creating a staged delivery when it still matches current authority and a quarantined one with bytes retained when it does not (approved 2026-10-06). Accept bounded raw MIME transactionally before SMTP success. Staged records and accepted/quarantined payloads never expire automatically: age cannot prove an SMTP transaction abandoned. Explicit fenced cleanup remains an operating gate.
- A claim revalidates the bound issuer/subject/mailbox/generation against current active routes. Conflicts quarantine without reassignment. Leases fence acknowledgments; the importer commits every intended local delivery before acknowledgment.
- `Import` resolves frozen issuer/subject/mailbox owners, checks the returned store identity, groups aliases, and commits permanent mailbox receipts before acknowledgment. The opt-in app importer preopens all stores and holds domain/directory/users fences through commits and acknowledgment. Partial failure retains payload and retries after claim expiry; recipient reassignment quarantines rather than resolving the new owner.
- `OpenExisting` validates persisted limits/schema before enabling WAL and never initializes missing storage. `QuarantinePending` retains bytes/bindings and refuses active competing claims; its caller must prove current ownership/generation conflict under authority fences.
- SQLite FULL synchronization and immediate writer transactions protect receipt/payload atomicity. Finite payload/record limits and physical admission estimates refuse growth; file lengths and filesystem free-space plus next-write allowance are checked inside the writer transaction. Near-budget checkpoints run outside it only with measured WAL-copy growth plus recovery headroom; insufficient/unreadable headroom skips reclamation and refuses growth after exact-replay checks. Exact Bind/Accept replays and accepted-mail recovery remain available; physical/volume hard quotas remain deployment gates. No silent eviction.
- `Acknowledge` archives in its lease-fenced writer transaction: the delivery and bindings become one `archived` tombstone (gateway, id, sender, digest, recipients, `archived_at` UTC unix seconds, `disposition` `imported`/`released`/`discarded`/`partially_released`; opening a store whose `archived` table predates it adds the column with default `imported` after a plain-read check) outside the record limit, which therefore counts only staged, pending and quarantined deliveries. Tombstones answer exact Bind/Accept/Acknowledge replays, refuse a new recipient, sender, bytes or digest, and stop `Bind` from reopening the ID; `Get` reports `archived`, `Claim` refuses and `List` omits it. Every open reads first, through the partial `imported` index, and only then takes the writer lock to archive `imported` rows from an earlier or downgraded binary (`INSERT OR IGNORE` plus delete, one transaction). `ArchivedColumns` is the shape restore validation requires.
- `Quarantine` is the hosted gateway's frozen-binding record when current authority no longer matches: it creates a `quarantined` delivery with bytes and one binding, or moves a `staged` delivery with that exact binding and sender to `quarantined` with bytes; it refuses `pending` (use `QuarantinePending`), replays exactly and checks capacity without eviction. An all-empty owner marks an unresolved binding (unknown table revision, `Binding.Unresolved`). `ResolveQuarantined` binds it to an administrator-chosen owner (the caller proves current ownership under the import fences) and leaves it quarantined for `Release`; it refuses resolved bindings, other changes and a live release lease, and repeats harmlessly. `ImportTo` is `Import` into `INBOX` or `Junk` (receipt identity excludes the folder); callers keep a Junk verdict durable until the delivery is archived.
- `Release` is `Import` for a `quarantined` delivery: it leases it while it stays `quarantined` (the importer never sees it), skips the route check (its trusted caller must re-admit every frozen owner under the import fences first), commits the same mailbox receipts and archives as `released`. `Discard` archives a `quarantined` delivery without a live lease as `discarded`, or as `partially_released` when its `lease` is set: every path into quarantine clears the lease and only `Release` sets one, so a set lease means a release started and some frozen mailboxes may hold the mail. Keep that invariant if you add a quarantine path. Repeats of either succeed only against their own dispositions. `ListQuarantined` pages envelopes and bindings without reading MIME. `ValidIdentifier` is the gateway/ID rule for callers' boundaries.
- Tombstones are never pruned yet: typically ~190-210 B (about 2 million in the default physical budget), attacker-shaped (320-byte sender, 100 recipients) about 170K, and `ingress.db` reaches the 64 MiB backup file cap near 360K. A full budget stops reception permanently because durable limits cannot be raised; pruning by `archived_at` or by proven source deletion is a public-MX gate.
- `Blocks` is the manual (and, later, automatic) sender block list, `sender-blocks.json` beside `ingress.db`: its own file under its own lock, so no writer touches the SQLite spool. Writes refuse without an existing receiving directory and never create it. Values are normalised lowercase ASCII that the Worker accepts (non-ASCII refused before lowercasing); `Put` refuses the caller's own domains and addresses on them, past `until`, free-text reasons, and more than 5000 entries or 512 KiB of wire. `Remove` takes the 16-hex `BlockID`. `Blocked` matches a whole address or exactly a domain (U-label senders via IDNA), never the null sender. A malformed file refuses every read rather than dropping blocks.
- Raw mail, envelope metadata, WAL and local database backups may contain plaintext. Do not claim end-to-end confidentiality or write correspondence to application logs.

## Work Guidance

- Reuse installed SQLite and fsutil; preserve raw bytes without MIME reconstruction.
- Keep public deployment gated by receiver abuse/capacity, TLS, provenance and recovery qualification; app command integration does not install a receiver.

## Verification

- `GOTOOLCHAIN=go1.26.6 go test -race ./internal/ingress -count=1` checks retention, archival (record limit, replay, atomicity, legacy migration), release/discard (frozen owners, interrupted release, discard tombstone replay, envelope-only listing), fencing, immutable ownership, quotas, physical admission/recovery, pinned-reader WAL reclamation, competing-process refusal and transaction replay.
- `TestSenderBlocks` checks block normalisation, refusals, matching, expiry, cap, wire budget, concurrent writers and the never-create-the-directory rule.
- Linux `TestHoldingCheckpointHeadroom` mounts a disposable 48 MiB tmpfs in a private user/mount namespace to check real checkpoint-growth refusal; it explicitly skips when `unshare` or mounting is unavailable. It never fills a shared host filesystem.
- Set `MADDY_PROOF_BINARY` to the pinned binary in `docs/RECEIVING_GATEWAY_ASSESSMENT.md` to run the real receiving integration test; absence skips that test explicitly.
- `GOTOOLCHAIN=go1.26.6 go test -race ./internal/app -run '^TestNativeReceiving|^TestNativeQuarantine' -count=1` checks actual receiving commands/import, deadline, revocation, quarantine, quarantine release/discard through the CLI and quota recovery. Supply the same pinned binary to exercise actual Maddy command dispatch.
